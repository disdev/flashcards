Module 1 · Foundations03

Out of the box: brilliant, and blind

What the model brings
  • Reasoning, planning and synthesis across domains
  • Fluent writing, code and analysis on demand
  • Broad knowledge of the public world
  • Native ability to use tools when you hand it some
What it can't know or do alone
  • Your private data wikis, tickets, warehouse, CRM, code — none of it was in training
  • Anything after its training cutoff
  • Taking real actions it can describe a fix; it can't file the ticket
  • Grounding asked about your world with no access, it guesses — that's the hallucination you've met

Think of it as a brilliant consultant on day one — sharp as anyone you've hired, but no badge, no laptop, no logins.

Module 2 · Context engineering04

Context is the whole game

The context window is the model's working memory. Answer quality tracks context quality almost one-for-one — so the real engineering question is: how does the right information get in there?

Paste it in A human copies the doc, the error log, the spreadsheet into the chat by hand. Fine for one-offs. Doesn't scale, goes stale instantly.
Retrieve it A pipeline searches your corpus and injects relevant passages automatically (RAG). Great for Q&A over large, mostly-static document sets.
Let the model fetch it The model calls tools itself — queries the database, reads the ticket, hits the API — deciding what it needs as it works. Live systems + actions. This is where MCP lives, and where this course spends most of its time.

These compose — real assistants usually use all three.

Module 3 · Why a protocol05

The integration tax

Before a standard existed, every AI app needed custom glue for every system it touched: N apps × M systems = N×M bespoke, brittle integrations — each with its own auth, its own bugs, its own owner.

AI apps Claude / chat assistant Coding agent Support copilot
Your systems Data warehouse Wiki / docs CRM & tickets GitHub / CI

Twelve integrations for three apps and four systems — and you haven't shipped a feature yet. This is the problem MCP exists to delete.

Module 3 · Model Context Protocol06

MCP: one port, any system

Model Context Protocol — an open standard (Anthropic, 2024; now adopted across the industry) for connecting AI apps to data and tools. Think USB-C for AI: build one MCP server per system, and every MCP-capable app can plug into it. N×M collapses to N + M.

Warehouse server Wiki server CRM server GitHub server

Module 3 · Protocol primitives07

Three things a server can offer

Tools · model-controlled

Actions the model may take

Functions the model chooses to call while it works — the workhorse primitive.

query_warehouse(sql)
create_ticket(title, body)
search_docs(query)

Resources · app-controlled

Data the app can attach

Readable context — files, schemas, records — that the host app pulls into the conversation.

file:///specs/api.md
crm://accounts/ac-1042

Prompts · user-controlled

Workflows users invoke

Reusable templates a person picks from a menu — the "slash commands" of your integration.

/triage-incident
/weekly-metrics-review

Transports are boring on purpose: stdio for local servers, streamable HTTP for remote — same primitives either way.

Module 4 · How agents actually work08

The agentic loop

Give a model tools and a goal, and it runs a loop — no flowchart you wrote, just the model deciding what it needs next. Your leverage is the quality of the tools and the guardrails, not scripting each step.

01 · PLAN

Read the goal

"Why did checkout conversion dip last week?"

→
02 · ACT

Call a tool

query_warehouse(…) — the request travels over MCP to your system.

→
03 · OBSERVE

Read the result

Rows come back into context. The dip started Tuesday, mobile only.

→
04 · REFINE

Decide what's next

Check Tuesday's deploys → list_releases(…) — or answer, if it has enough.

⟲  REPEAT UNTIL DONE — typically 3–15 tool calls per real task
Module 4 · Choosing a pattern09

Matching the pattern to the data

Prompt stuffing Small, stable reference material — put it straight in the system prompt or attach the file. style guides · policies under ~50 pages · schemas
Classic RAG Embed a large corpus once; retrieve semantically similar chunks per question. knowledge bases · past tickets · contracts
Agentic search via MCP The model queries live systems with real query languages — SQL, API filters, code search — and iterates on what comes back. warehouses · CRMs · repos · anything with an API
Actions via MCP Beyond reading: the model files the ticket, opens the PR, sends the summary — with approval gates where it matters. write paths · workflows · automation

Rule of thumb: static knowledge → retrieval; live state or side-effects → tools.

Module 5 · Trust & safety11

New capability, new attack surface

The moment the model can read your data and touch your systems, security stops being someone else's module. Four disciplines, non-negotiable:

01 · Prompt injection

Everything a tool returns — web pages, tickets, emails — is untrusted input that can carry instructions. Treat retrieved content as data, never as commands; sanitize and sandbox accordingly.

02 · Least privilege

Scoped tokens, read-only by default, per-user auth (OAuth) so the model can only see what that user could already see. Never a god-mode service account.

03 · Human in the loop

Reads can flow freely; writes and irreversible actions get an approval gate. Deleting records and emailing customers are earned privileges, not defaults.

04 · Audit & evals

Log every tool call with inputs and outputs. Build an eval set before you scale, so "it seems fine" becomes a number you can watch.

Module 5 · Craft12

Your tools are prompts

The model reads your tool names, descriptions and errors the way a developer reads docs. Tool design is the highest-leverage prompt engineering you'll do.

  • Fewer, sharper tools. A handful the model can't confuse beats forty that overlap.
  • Write descriptions for the model. When to use it, when not to, what a good call looks like — with examples.
  • Pick the right altitude. schedule_meeting(person, topic), not five raw calendar endpoints the model must choreograph.
  • Budget tokens. Return what the task needs and paginate the rest — a 50,000-row dump helps no one.
  • Errors that teach. "date must be ISO-8601, e.g. 2026-07-06" lets the loop self-correct; "400 Bad Request" ends it.

Lab 4 is exactly this: you'll build and ship a small MCP server against one of our real systems.
